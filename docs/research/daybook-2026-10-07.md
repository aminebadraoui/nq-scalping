# Daybook — the DB-less system journal (2026-10-07)

## Why

The 2026-10-07 post-mortem found the trade journal dead:

- The live dashboard container had no `DATABASE_URL` → `exec_log`, `signals`,
  `guard_state`, `trade_analysis` were memory-only, wiped by the 08:37 ET
  redeploy, and `/api/trades` returned `{ok:false, "no DATABASE_URL"}`.
- Neon was quota-blocked (`Your account or project has exceeded the quota` —
  monthly data-transfer cap exceeded; storage at 412/512 MB and climbing),
  refusing NEW connections, so the nightly ingest/reconcile/analysis steps
  could not run at all.

**Can we keep using the DB?** Storage works — the binding constraint is
EGRESS. The workload shape (nightly re-ingest of a 3-week candle window +
dashboard readthrough queries) will keep blowing the free-tier transfer cap
even after a reset. Neon can stay for the rich analytics (equity curve,
scoreboard, hour matrices) whenever it is reachable — but the journal must
not depend on it.

**The DB-less solution:** the daybook. One append-only JSONL per NY trading
day at `GC_DATA_DIR/daybook/<day>.jsonl`, written by the live dashboard
(persistent Coolify volume at `/app/data`) and archived to Cloudflare R2
(free egress) by the nightly jobs container.

## Record types

| t | writer | content |
|---|--------|---------|
| `boot` | dashboard boot | variation fingerprint: git SHA (`BUILD_SHA` ← Coolify `SOURCE_COMMIT`) + full settings snapshot (every strategy/risk/feed knob, secrets masked to a stable sha256 prefix) → `variationId` |
| `signal` | signalFeed → signalHistory | every card emitted AND every veto/skip with entry/stop/target + features (skips were DB-only before) |
| `exec` | execLog | every order attempt/watch decision (redeploys can no longer destroy the evidence) |
| `guard` | accountGuard.save() | day reference + protection state on meaningful events (rollover/arm/dd) |
| `heal` | live.ts | every tape-gap stall episode closed: episode number, ladder steps, duration |
| `dayend` | scripts/daybookConsolidate.ts (nightly) | the consolidated day summary (trades, W/L, net, heal episodes, cap-skip replay, expRetrace quality) |

## Consolidation (nightly, DB-less)

`scripts/daybookConsolidate.ts` pulls the live JSONL from
`/api/daybook?format=jsonl`, reconstructs every trade from the CrossTrade
fill/order record (order-level via `parentId` + sibling-`ocoId` resolution,
fill-level fallback after the ~17:00 session reset), labels trades with
their signal cards, replays RTH cap skips against the collected tape, and
writes `<day>.summary.json` + the `dayend` record. `r2_sync.py upload`
archives the `daybook/` dir.

## Read path

- `GET /api/daybook` — the variation index (fingerprint per day + summaries).
- `GET /api/trades` — falls back to the daybook summaries whenever the DB is
  absent or unreachable.
- `GET /api/gc?action=health` — `buildId` is now the deployed SHA; `domFeed`
  shows the DOM_V2 frame counters; `liveFeed.heal` shows the ladder state.

## The variation log

Every push to `main` auto-deploys → the new process writes a `boot` record
with its `variationId`. The index (`/api/daybook`) therefore shows, per day:
which variation ran, its exact settings, and its day P&L — the settings
fingerprint makes any knob change visible as a new variation.

## Env knobs

- `DAYBOOK_OFF=1` silences journal writes (set by the test loader).
- `BUILD_SHA` — injected by the Dockerfile from Coolify's `SOURCE_COMMIT`
  build arg (`include_source_commit_in_build=true` on the Coolify app).
- `DASHBOARD_URL` — where the consolidation pulls the live JSONL from
  (default: the sslip dashboard URL).
